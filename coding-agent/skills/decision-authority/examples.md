# 判断例

代表的な開発場面での、このスキルに沿った判断を示す。「規則」は SKILL.md の行動規則の番号。

## 1. 仕様と食い違う挙動のバグ修正

- 場面: 仕様書に「税額は1円未満を四捨五入」とあるが、実装は切り捨てている。利用者からは「合計金額がずれる」とだけ報告された。
- 判断: 仕様書が意図の証拠なので、確認せずに四捨五入へ直し、切り捨てを前提にしていたテストも直す。報告では、過去の請求額に差が出ていた可能性に触れる。
- 規則: 2、5

## 2. 意図が確認できない既存挙動に当たったリファクタリング

- 場面: 一覧APIの整理中に、該当なしのとき空配列ではなく `null` を返すことに気付いた。文書にもコメントにも理由がない。
- 判断: 公開APIの応答で外部から観測されるため、リファクタリングでは挙動を変えない。`null` を仕様として固定するテストも追加しない。空配列に揃える案を報告で提案する。
- 規則: 2、6

## 3. 内部に閉じた挙動の変更

- 場面: 性能改善の依頼。内部キャッシュの破棄が、件数上限で古い順に行われている。理由の記録はない。
- 判断: 外部から観測されず戻しやすいので、計測に基づいて方式を変える。確認は求めない。
- 規則: 2、5

## 4. 新機能で設計の決定が必要になる

- 場面: 「ユーザーを削除できるようにして」と依頼された。削除の方式についての決まりはない。
- 判断: 論理削除か物理削除かは、データ保持や復元の可否、関連データの扱いに関わり、後から戻しにくい。選択肢とトレードオフ、推奨を示して同意を得る。その間に、方式に依存しない画面や権限チェックは既存の規約に沿って実装を進める。
- 規則: 4、5

## 5. 既に人間が決めた事項

- 場面: 会話の冒頭で利用者が「保存先はSQLiteにする」と決めた。実装の途中で、別の機能のために保存処理を追加することになった。
- 判断: 確認せずSQLiteを使う。ただし、同時書き込みが多い要件が新たに判明し、SQLiteでは満たせない根拠があるときは、その根拠を添えて一度だけ見直しを提案する。
- 規則: 3

## 6. 要件そのものに問題がありそうなとき

- 場面: 要件に「パスワード再設定リンクの有効期限は30日」とある。
- 判断: 期限を独断で変えない。安全上の懸念と代案（例: 1時間）を示して判断を求める。回答を待つ間は、期限の値に依存しない部分を実装する。
- 規則: 4

## 7. 理由が書かれた奇妙なコード

- 場面: 外部決済の呼び出しに「決済代行の規約により再試行は2回まで」というコメントがある。通信処理を共通化したところ、共通の再試行回数は3回になる。
- 判断: コメントは意図の証拠なので、決済だけ2回に保つ。共通化の方法（回数を引数にするなど）はAIが決める。
- 規則: 2、5

## 8. 現在の出力を写しただけのテストが失敗する

- 場面: 日付表示のバグ（タイムゾーンの扱い）を直したら、スナップショットテストが失敗した。
- 判断: スナップショットは現在の出力を写したもので意図の証拠ではない。修正後の正しい出力でスナップショットを更新する。一方、「削除済みユーザーには404を返す」のように意図を名前で表すテストが失敗した場合は、自分の変更が仕様を破っていないかを先に疑う。
- 規則: 2

## 9. 依存の追加

- 場面A: テストで使う日付のモックのために、小さな開発用ライブラリを追加したい。プロジェクトに依存追加の決まりはない。
- 場面B: 既存のORMを別のORMに置き換えたい。
- 判断: Aは影響が開発環境に閉じていて戻しやすいので、確認せずに追加し、報告で触れる。Bはデータアクセス全体を拘束するので、理由とトレードオフを示して提案する。
- 規則: 5

## 10. 判断を委ねられたとき

- 場面: 「内部APIの設計は任せる。外部に公開するAPIは今のまま」と指示された。
- 判断: 内部APIは確認せずに設計し、主な決定を報告で示す。公開APIは変えない。
- 規則: 3

## 11. 仕様書を書く作業

- 場面: 実装済みのコードから仕様書を起こすよう頼まれた。
- 判断: 意図の証拠がある挙動は仕様として書く。証拠のない挙動は「現在の挙動（意図未確認）」と区別して書き、判断が必要な点を一覧にして示す。
- 規則: 2、4

## 12. プロジェクトの規約がより多くの確認を求めている

- 場面: CLAUDE.md に「DBスキーマの変更は必ず事前に相談する」とある。依頼された機能のために、検索用の索引を1つ追加したい。
- 判断: プロジェクトの規約が優先する。索引もスキーマの変更なので、追加する理由を示して確認する。
- 規則: 3、「他の指示との関係」
