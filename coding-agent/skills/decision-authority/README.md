# decision-authority

ソフトウェアを変更する作業で、人間が決めるべき事項（要件・設計仕様）とAIが自律的に決めてよい事項（実装）を、設計意図に基づいて区別する Claude Code Skill。この文書は人間向けの設計説明であり、SKILL.md から参照していないため通常は Claude に読み込まれない。

## 構成

| ファイル | 読み手 | 内容 |
|---|---|---|
| `SKILL.md` | Claude | 概念、権限の方針、行動規則 |
| `examples.md` | Claude と人間 | 代表的な場面での判断例。SKILL.md から参照し、境界の判断に迷うときだけ読み込まれる |
| `README.md` | 人間 | この文書 |

## 設計方針

### 概念と方針を分ける

SKILL.md を「概念」「権限」「行動規則」に分けた。概念は要件・設計仕様・実装挙動の定義と性質だけを述べる。権限はこのスキルが採用する方針であり、概念から導かれる必然ではないと明記した。こうしておくと、プロジェクトや利用者が権限の割り当てを変えても、概念の理解は変わらない。

### 判断の軸を「分類」ではなく「何を決めることになるか」に置く

作業対象を3分類のどれかに当てはめる作業は、観点によって答えが変わるため、それ自体を判断基準にすると迷いや形式的な分類作業を生む。行動規則では「要件や設計仕様を新たに決める、または変えることになるか」「人間が知らないうちに拘束力のある決定が生まれるか」を問うようにした。分類は理解の道具にとどめる。

### 意図の有無は証拠で判断し、証拠がないときの扱いを決めておく

「現在の挙動は意図を意味しない」という原則だけでは、AIは既存挙動を自由に変えてよいと誤解しうる。逆に「意図を創作しない」だけでは、すべてを確認対象にしうる。そこで、意図の証拠になるものとならないものを挙げ、証拠がない場合の扱いを外部への影響と戻しやすさで分けた。証拠がなくても外部から観測される挙動は、黙って変えず、仕様として固定もせず、提案に回す。

### 確認の対象を絞る

承認が必要な設計判断を「外部から見える、戻しにくい、または広い範囲を拘束する決定」に限定し、局所的な設計上の選択は実装判断として扱う。確認すべきか迷ったときは、判断を誤った場合の影響と戻しやすさで決める。確認はまとめて一度に行い、回答を待つ間も決定に依存しない作業は進める。

### 依頼と既存の指示を人間の決定として扱う

依頼そのものを要件への同意とみなし、依頼に明記された事項は確認し直さない。「任せる」と委任された範囲では設計判断もAIが行う。プロジェクトの規約（CLAUDE.md など）は人間の明示的な決定なので、このスキルより多くの確認を求めていても、広い自律を認めていても、規約に従う。

### Claude Code 本体の安全確認とは分ける

このスキルは「何を誰が決めるか」だけを扱う。ツールの実行許可や、破壊的な操作・外部への公開の前の確認は Claude Code 本体や環境の仕組みであり、このスキルでは緩めも強めもしない。

### 手続きを増やさない

承認フロー、チェックリスト、判断記録の作成を義務にしない。報告で区別して書く事項（判断待ちの提案、仮定、重要な実装判断）も、該当するときだけ書く。SKILL.md は呼び出されると以後の会話に残り続けるため、規則は短くし、判断例は別ファイルに分けた。

## 作成時に検討した懸念と対応

| 懸念 | 対応 |
|---|---|
| 3分類を意図の強さの序列と誤解する | 概念の節で、序列ではなく役割と性質の違いであることと、観点で分類が変わる例を示した |
| 現在の挙動と意図された仕様を区別できない | 意図の証拠になるもの・ならないものを列挙した。スナップショットテストやAI自身が書いたコードは証拠にならないと明記した |
| 要件と設計仕様の境界を厳密にしすぎる | 境界の判定を求めず、「何を決めることになるか」で判断させた。権限の対応も例外を許す原則とした |
| 自律性を損なう | 確認せずに行う作業を具体的に列挙し、日常の実装判断まで確認することを方針の失敗と明記した |
| 明示された指示の扱い | 依頼そのもの、会話での決定、委任、プロジェクトの規約を人間の決定として扱い、再承認を求めないとした |
| Claude Code の既存の仕組みと矛盾する | 優先順位（利用者の指示、プロジェクトの規約、このスキル）を定め、権限確認や安全確認とは別のものとした |

## 導入

```sh
ln -s ~/dotfiles/coding-agent/skills/decision-authority ~/.claude/skills/decision-authority
```

Skill は description が作業内容に合うと Claude が判断したときに読み込まれる。どの作業でも確実に適用したい場合は、グローバルまたはプロジェクトの CLAUDE.md に次のような一文を加える。

```markdown
- ソフトウェアを変更する作業では `decision-authority` スキルに従う。
```

`/decision-authority` で明示的に呼び出すこともできる。
